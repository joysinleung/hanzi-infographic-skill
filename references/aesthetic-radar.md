# 美学评审雷达（5 维）· 源自 huashu-design 方法论

> 把 huashu-design 的「5 维专家评审（哲学/层级/执行/功能/创新）」范式搬进 hanzi 美学门控，适配为信息图场景的 **5 维 × 20 分 = 100 分** 结构性启发式打分。**< 90 分阻止交付**（对齐 qa-checklist 100 分门控）。

## 为什么做

hanzi 原美学门控靠人工看（qa-checklist 失败信号靠人眼）。引入雷达后，把"美不美"变成"5 维打分过不过"，补齐产线**质量量化**短板。脚本对渲染前 HTML 做结构性检查（不依赖像素），是**客观预检 + 人工终检**的互补。

## 5 维定义与判据

| 维度 | 含义 | 启发式判据（结构性） |
|------|------|---------------------|
| **hierarchy 视觉层级** | 标题/区块/正文有清晰字号梯度 | 最大字号≥32、正文≥24、梯度≥12px |
| **density 信息密度** | 板块有内容、不空洞、不堆砌 | 板块数≥3、点睛图/板块比≤0.6（铁律 2-4 个重点） |
| **whitespace 留白呼吸** | 容器/区块内边距合理、不触边 | padding≥24、margin≥12、gap≥12 |
| **consistency 一致性** | 语义色克制、无 slop 杂色 | 语义色类(红/橙/蓝/绿)使用、内联 hex ≤ 6 种 |
| **readability 中文可读性** | 中文清晰可渲染 | lang=zh、CJK 字体、await fonts、无<18px 极小字 |

## 用法

```bash
node scripts/aesthetic-radar.cjs <task>/index.html [--json <task>/radar.json]
# 退出码 0 = 总分≥90（过门控）；1 = <90（阻止交付）
```

## 与 qa-checklist 的关系

- `verify.cjs`：技术门控（板块数/尺寸/非黑屏/中文不乱码）
- `aesthetic-radar.cjs`：**美学门控自动化**（5 维打分）
- 人工目视：最终过 qa-checklist 失败信号（不 PPT 化/不模板堆砌/墨方承担动作）

三者共同构成"技术 + 美学 + 人工"三重门控。**雷达是客观预检，不替代人工终检**——它抓的是结构性 slop（杂色/极小字/装饰堆砌/无层级），抓不到的是"像不像教程页"这类主观判断。

## 边界

- 脚本只读 HTML/CSS 结构，不解析最终像素布局；无法判"死板无记忆点""太像 PPT"等需人眼项。
- 任一维度显著低分（如 consistency 因杂色扣分），先修 CSS 再重渲染，不要靠人工放过。
